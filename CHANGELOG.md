## [4.2.7](https://github.com/sany86russ/StabiLink-Desktop/releases/tag/v4.2.7) — 24 октября 2026

Последняя публичная версия объединяет доработки 4.2.1–4.2.7: устойчивее DNS и совместная работа Оптимизатора с SecureLink, понятнее диагностика приложений и память в Performance Hub.

### DNS, Phantom и SecureLink

- Проверки DNS отдельно учитывают IPv4 и IPv6. Корректное отсутствие IPv6-адреса не считается ошибкой, быстрый IPv4 не скрывает повторяющиеся задержки IPv6.
- При подтверждённом сбое Оптимизатор может временно применить проверенный защищённый DNS, проверить результат и вернуть собственные изменения, если улучшение не подтверждено. При исправном DNS, корпоративной политике или независимом DNS-управлении настройки остаются прежними.
- После штатного отключения SecureLink есть ограниченная проверка прямого DNS; успешный результат через VPN не заменяет её.
- SecureLink корректно разделяет типы DNS-запросов для выбранных доменов, восстанавливает доступность резолверов после временных сбоев и не принимает запоздалые ответы прежней сети за новый успех.
- Phantom и его варианты WARDOGS получили обновлённый HTTPS-путь Google/YouTube. Отдельные игровые правила и голосовые исключения Discord сохранены.
- Приложения в Split Tunnel направляют через VPN IPv4. IPv6 поддерживается для выбранных доменов и явных IPv6-подсетей при поддержке сервера. Прямые исключения сохраняют приоритет.
- TurboDNS сохраняет контроль над своим процессом при неподтверждённом завершении. Новый процесс не запускается поверх ещё работающего.

### Диагностика, память и обновления

- Проверка сайта явно показывает успех «через резерв», если основной адрес не ответил, а CDN доступен. Исходная ошибка, DNS/TCP-метрики и затраченное время сохраняются.
- Можно записать короткую диагностику выбранной программы: нагрузку, память, время сбоя и доступные поддерживаемые журналы. Экспорт локальный, с маскировкой чувствительных данных и без автоматической отправки.
- Performance Hub показывает физическую ОЗУ, выделенную память, запас и крупных потребителей отдельно. Автоматического сброса кэша по таймеру нет; ручное обслуживание ограничено низкоприоритетным кэшем при подтверждённой нехватке.
- Итоги игровой сессии сохраняются после выхода из игры и перезапуска Desktop. Поиск игровых библиотек откладывается во время игры.
- Загрузка обновлений имеет ограниченное ожидание начала передачи и повторные попытки при временном сбое. Медленная передача, которая продолжает идти, не обрывается общим таймером.
- Автосмена вариантов, запоминание удачных вариантов и группировка отправки пакетов выключены по умолчанию. Ускоренный движок работает независимо от них.

Каталог сохраняет **36 стратегий: 8 общих и 28 игровых для 9 игр**. DNS-проверка не является измерением игрового ping; наличие профиля не доказывает длительный матч на каждом провайдере. Отдельные GitHub Releases 4.2.1–4.2.6 здесь не публиковались.

### StabiLink 4.2.6 — устойчивее DNS, Phantom и Split Tunnel

Доработали обработку отрицательных ответов DNS и HTTPS-правило Google/YouTube в Phantom. Уточнили IPv6 в SecureLink: выбор приложения направляет через VPN его IPv4-трафик, а IPv6 сохраняется для выбранных доменов и IP-подсетей при поддержке сервера. Обычный IPv6 остальных соединений остаётся в сетевом стеке Windows.

#### 🌐 Проверка отрицательных ответов DNS SecureLink

- В DNS SecureLink ответ обычного DNS «имя не найдено» для публичного домена перепроверяется через защищённый DNS по HTTPS в пределах общего двухсекундного бюджета запроса. Это позволяет обойти ложный отрицательный ответ, когда защищённый резолвер возвращает действительный адрес.
- Если защищённый резолвер подтверждает отсутствие имени, ответ сохраняется. Если перепроверка недоступна, сохраняется исходный отрицательный ответ с явной записью в журнале; такой результат не делает резолвер предпочтительным.
- Локальные имена и защищённые корпоративные DNS-области остаются на локальных резолверах. Ответ без адресов для существующего имени не запускает эту перепроверку.
- Изменение не расширяет список сайтов SecureLink и не требует перезапуска исправного туннеля для каждого переключения DNS.

#### 🌐 Дополнение 23 октября: DNS без SecureLink

- Проверка DNS Оптимизатора учитывает YouTube и Mail вместе с контрольными доменами, чтобы обнаруживать выборочные сбои при работающем остальном интернете.
- После штатного отключения SecureLink Оптимизатор один раз проверяет прямой DNS-путь: использует оставшийся бюджет пропущенной стартовой проверки либо отдельную ограниченную фазу, если прежний DNS проверялся через VPN. Перезапускать Оптимизатор для этого не требуется.
- Лимиты применения, проверка защищённого резолвера, отмена и восстановление собственной политики сохранены. Сетевые события не запускают бесконечные повторы; игровые и голосовые правила не меняются.
- Это отдельная доработка автономного режима. Перепроверка отрицательных DNS-ответов выше относится к работающему SecureLink.

#### 🌐 Дополнение 23 октября: общая устойчивость DNS

- Проверка DNS Оптимизатора учитывает A и AAAA. Правильный ответ об отсутствии IPv6-адреса не считается ошибкой; повторяющиеся задержки AAAA больше не скрываются за быстрым IPv4.
- Для временного исправления выбираются только проверенные адреса защищённого DNS Cloudflare или Google. Недоступность одного адреса не блокирует исправный второй, а смена подключения во время проверки не расходует попытку применения.
- SecureLink разделяет DNS-запросы по типам: A/AAAA сохраняют fake-IP для выбранных доменов; HTTPS/SVCB/ANY получают быстрый пустой ответ в этих же областях, TXT/MX/SRV обрабатываются обычным DNS-механизмом. Прямые исключения и whitelist сохраняются.
- DNS SecureLink может восстановиться после краткого сбоя до истечения 30-секундной паузы. Проверки ограничены по частоте и числу; зависший запрос не разрешает запускать новые обращения к тому же адресу.
- TurboDNS сохраняет контроль над своим процессом, если его завершение не подтверждено, и повторяет очистку при следующем отключении.
- Если проверка YouTube прошла только через резервный адрес CDN, журнал и статистика прямо показывают это и сохраняют сведения о неудаче основного адреса.

#### ⚡ Phantom: HTTPS для Google и YouTube

- Заменили отдельный HTTPS-приём для узкого списка Google/YouTube на уже используемый в Phantom веб-приём. Изменение применяется к Phantom и его вариантам WARDOGS с сохранением списка доменов и прямых исключений.
- Для сохранённого доверенного каталога исправляется только точное старое правило. Пользовательские стратегии и отличающиеся настройки не подменяются.
- Игровые порты, UDP, авторизация WARDOGS и голосовые правила Discord сохранены. Контроль HTTPS-соединения не подтверждает воспроизведение видео или работу всех сайтов в браузере.

#### 🔗 SecureLink и Split Tunnel

- Убрали широкий захват IPv6 при запуске выбранного приложения. Наличие IPv6-адреса и маршрута у физической сети больше не включает такой захват.
- Выбранные домены и явно заданные IPv6-подсети сохраняют поддержку IPv6 через SecureLink. IPv4-подсеть не расширяется автоматически на IPv6.
- Подключение к серверу SecureLink и повторные попытки используют IPv4. Это не отключает IPv6-выход сервера для выбранных доменов и подсетей; профиль сервера должен содержать доступный IPv4-адрес или имя с IPv4-ответом DNS.
- Сохранили приоритет прямых исключений. Трафик вне доменных и IP-правил IPv6 не переводится в VPN только из-за правила для приложения.
- Изменение или временная недоступность сведений о физическом IPv6 больше не пересоздаёт и не блокирует работающие маршруты приложений для IPv4.

#### 🛡 Очистка и понятные настройки

- Сохранена очистка IPv6-маршрутов, которыми приложение уже владеет. Если удаление не подтверждено, контроль над ними сохраняется для повторной попытки; чужие маршруты не удаляются.
- В настройках прямо указано, какие правила поддерживают IPv4, а какие — IPv4 и IPv6.

Правило только для приложения не обеспечивает передачу произвольного IPv6 через VPN: нужен подходящий домен или IPv6-подсеть в правилах SecureLink. Это относится и к буквальному IPv6-адресу, и к реальному IPv6-ответу DNS для домена вне списка. SecureLink не является глобальной блокировкой обхода VPN.

**При обращении в поддержку** укажите сервис или игру, выбранную стратегию, состояние SecureLink и время сбоя. При необходимости приложите диагностический отчёт из StabiLink.

### StabiLink 4.2.5 — IPv6, устойчивее Split Tunnel и полезнее диагностика

В этой версии доработали совместную работу SecureLink и Оптимизатора трафика, добавили IPv6 в раздельную маршрутизацию и автоматический резерв DNS. Performance HUB стал понятнее показывать использование памяти, а диагностика помогает сохранить сведения о проблеме конкретной программы или игры.

#### 🔗 SecureLink и Split Tunnel

- Раздельная маршрутизация поддерживает IPv4 и IPv6 для выбранных доменов и IP-сетей. Широкий захват IPv6 выбранных приложений включается при пригодном IPv6-адресе физической сети; явные исключения для прямого подключения имеют приоритет.
- IPv6 для выбранных доменов и подсетей может работать через SecureLink даже при IPv4-подключении к VPN-серверу. Поддержка определяется профилем сервера автоматически.
- Исправили широкий захват IPv6 в сети, где есть маршрут IPv6, но нет пригодного адреса для прямого выхода в интернет. Обычные приложения сохраняют возможность перейти на IPv4; их трафик не переводится в VPN из-за этой проверки.
- Заменили служебный IPv6-диапазон для выбранных доменов, чтобы браузер не принимал их за устройства локальной сети. Защита браузера и разрешения сайтов не отключаются.
- Устранили переключение IPv6-привязки во время запуска TUN. Подготовка выполняется до старта ядра, только для собственного адаптера StabiLink.
- При временной ошибке определения пути программы сохраняется уже подтверждённый захват её процесса. Поздние события старого подключения не сбрасывают новый сеанс.

#### 🌐 Автоматический резерв DNS SecureLink

- Если основной DNS не отвечает или возвращает временную ошибку, SecureLink автоматически пробует резервные серверы. В пул входят обычный DNS и защищённый DNS через HTTPS.
- Ответы IPv4 и IPv6 проверяются отдельно: удачный запрос A не скрывает отказ AAAA.
- Рабочий резолвер временно получает предпочтение. Переключение DNS не требует перезапуска исправного туннеля.
- При смене сети обновляется набор DNS-серверов и физический интерфейс запросов; запоздавшие ответы прежней сети не используются.
- Распознанные локальные имена и защищённые корпоративные DNS-области остаются на локальных резолверах.
- Резерв обслуживает DNS-запросы SecureLink. Он не заменяет DNS физических сетевых карт и не расширяет whitelist приложений и сайтов.

#### 🛡 Совместимость с Оптимизатором трафика

- Перед подключением SecureLink проверяется исключение его транспортных адресов из обработки Оптимизатором. Учитываются IPv4 и IPv6, а также новые адреса при следующей попытке подключения.
- Если действующий движок не покрывает нужные исключения, выполняется управляемая замена Оптимизатора с сохранением стратегии, списков и пользовательских параметров.
- При неподтверждённой остановке процесса приложение сохраняет контроль над его ресурсами. Очистка не удаляет используемые или чужие маршруты.
- Исправили случаи, когда быстро завершившийся процесс мог нарушить дальнейшее автоматическое восстановление Оптимизатора.

#### ⚡ Движок и подбор стратегий

- В ускоренном движке исправили ритм внутренних таймеров после задержки обработки. Просроченные операции не выполняются длинной цепочкой подряд.
- Доработали обработку запоздалых повторных TCP-пакетов, чтобы они не откатывали состояние уже начавшегося соединения.
- Подбор стратегий учитывает фактические TCP/UDP-порты Game Filter. Результат для одного набора портов не используется как готовый ответ для другого.
- Уточнили отмену и завершение параллельных подборов: старый сеанс не освобождает ресурсы нового.
- Ускоренные режимы сохраняют независимость от автосмены вариантов, запоминания удачных вариантов и группировки отправки пакетов.

#### 🎮 Game Filter, Phantom и WARDOGS

- Исключённые веб-хосты сохраняют защиту от попадания в общее игровое правило, в том числе в совместимом движке.
- Копирование и сохранение стратегии, а также автоматическое уточнение варианта сохраняют эти исключения.
- Неизвестный игровой протокол не принимается за веб-соединение только по ранее сохранённому имени узла.
- Сохранены отдельные правила авторизации WARDOGS и голосовые исключения Discord. Изменения не обещают снижения игрового ping или прироста FPS.

#### 🧠 Понятнее использование памяти

- Автоматические очистки памяти заменены наблюдением за её состоянием. Оптимизатор ПК не сбрасывает кэши просто по таймеру.
- Физическая ОЗУ, выделенная память и доступный запас показываются отдельно. Видны крупные приложения, которым может требоваться внимание.
- Ручное обслуживание ограничено низкоприоритетным кэшем при подтверждённой нехватке ОЗУ. Рабочие наборы всех программ и файловый кэш не сбрасываются.
- Интерфейс показывает ограничения операции. Очистка кэша не выдаётся за освобождение памяти, которую приложения продолжают использовать.

#### 📊 Performance HUB и отклик сети

- Итог игровой сессии остаётся доступен после выхода из игры и перезапуска Desktop.
- Автоматический поиск игровых библиотек откладывается во время игры; временные изменения приоритетов снимаются до медленных фоновых проверок.
- История имеет ограничения по сроку и размеру, чтобы не накапливать лишние данные.
- Для контрольных узлов показываются отдельные измерения TCP-отклика. Это время установки соединения, а не игровой ping.
- При смене сети или истечении срока актуальности старый успешный результат не подменяет новую ошибку.

#### 📋 Запись проблемы приложения и отчёты

- Можно записать короткий сеанс диагностики выбранной программы: нагрузку CPU, память и отметки времени возникновения проблемы.
- При наличии доступа добавляются связанные ошибки Windows и поддерживаемые текстовые журналы Discord или WARDOGS.
- Сохраняется ограниченная история завершений Оптимизатора с причиной остановки и числовыми показателями работы движка.
- Экспорт содержит текущий и предыдущий журналы, историю и разрешённые настройки. Чувствительные данные очищаются перед сохранением.
- Сбор поддерживает отмену, ограничения времени и размера. Недоступные или неполные источники отмечаются в отчёте; автоматической отправки нет.

#### ⬇️ Обновление и завершение работы

- Обновлятор распознаёт собственные текущие и исторические движки во вложенных папках, сохраняя защиту чужих процессов.
- Перед заменой файлов и очисткой сетевых ресурсов подтверждается завершение принадлежащих StabiLink процессов.
- Отмена, ошибка чтения журнала или неудачная остановка не скрываются как успешное завершение операции.

Прямые исключения остаются прямыми: например, сайт вне туннеля может по-прежнему нуждаться в выбранной стратегии Оптимизатора. Поддержка IPv6 сама по себе не включает VPN для всего компьютера.

### StabiLink 4.2.4 — DNS и надёжность обновлений

В этой версии добавили автоматическую проверку DNS при запуске Оптимизатора. Она помогает устранить подтверждённые задержки открытия сайтов, в том числе при использовании Phantom (WARDOGS). Также доработали загрузку обновлений и диагностические отчёты.

#### 🌐 Проверка DNS при запуске Оптимизатора

- Если несколько контрольных сайтов повторно получают медленный ответ DNS или ошибку, StabiLink проверяет доступность защищённого DNS и возможность безопасного исправления.
- При быстром DNS настройки остаются прежними. Один недоступный сайт не запускает исправление.
- Проверки ограничены началом сеанса: постоянного опроса сайтов нет. За один запуск допускается одна попытка исправления; автоматическое восстановление процесса не обнуляет этот лимит.
- После применения StabiLink повторно проверяет результат. Если улучшение не подтверждено, возвращает прежние настройки.
- Исправление действует временно, до остановки Оптимизатора. Предусмотрено восстановление собственных изменений после аварийного завершения.

#### 🔗 Совместимость с SecureLink и локальной сетью

- Проверки учитывают текущее состояние SecureLink. Смена туннеля или его конфигурации отменяет прежний результат проверки.
- Временное исправление сохраняет DNS-правила SecureLink и исключения для локальной сети. DNS сетевых адаптеров и маршруты не меняются.
- Корпоративные политики, сторонний VPN и другие средства управления DNS имеют приоритет: в неподходящей сети автоматическое исправление пропускается.
- Перед изменением DNS проверяется готовность задачи аварийного восстановления.

#### ⚙️ Понятный статус и управление

- В Desktop отображается результат DNS-проверки: исправление не требуется, временно применено либо пропущено с указанием причины. Видно время последней проверки.
- В настройках можно отключить автоматическое исправление DNS. Временные изменения будут отменены, а Оптимизатор продолжит работу.
- После повторного включения настройка начнёт действовать при следующем обычном запуске Оптимизатора.

#### ⬇️ Надёжнее загрузка обновлений

- Ограничили ожидание ответа сервера до начала передачи файла, чтобы загрузка не оставалась на 0% без завершения.
- При временном сбое используются ограниченные повторные попытки и совместимый способ загрузки.
- Медленная загрузка, при которой данные продолжают поступать, не обрывается из-за общего лимита времени. Отмена пользователем сохранена.

#### 🛠 Более полезная диагностика

- Диагностический отчёт содержит результат DNS-проверки, состояние временного исправления и сведения о фактически запущенном движке Оптимизатора.
- В список компонентов включены движки во вложенных папках.
- Системные команды при сборе отчёта ограничены по времени и объёму вывода. Зависшая команда завершается отдельно от работающих компонентов StabiLink.

Выбранная стратегия, игровые правила и настройки SecureLink сохраняются. Автоматическое исправление DNS доступно вместе с бесплатным Оптимизатором.

**При обращении в поддержку** укажите сервис или игру, выбранную стратегию, состояние SecureLink и время сбоя. Приложите диагностический отчёт из StabiLink.

- При потере фокуса игры временные изменения её приоритета и режима энергопотребления возвращаются до следующего тяжёлого сбора показателей. Перед применением параметров повторно проверяется нужный процесс и активное окно.

- Обрезанный или неполный ответ QUIC больше не подтверждает удачный вариант подключения при включённой автосмене.
- Запоздалое завершение подбора, восстановления или сетевого обновления не отменяет более новое ручное отключение или переключение стратегии.

- Уточнили применение прямых IP-правил и проверку пересечений с внутренними сетями туннеля.
- Сократили лишние проверки игрового и голосового UDP, сохранив заданные правила маршрутизации приложений и доменов.

- Исправили обработку запоздалых событий старого сетевого процесса: они не сбрасывают состояние нового подключения.

- Уточнили различие между локальной ошибкой сокета и неудачным вариантом стратегии при подборе.

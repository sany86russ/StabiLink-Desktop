Этот документ относится к публичной витрине готовых сборок. Исходники приложения и приватная история Git сюда не переносятся. Точные разрешённые пути определяются действующим allowlist; он не расширяется автоматически.

## Проверка пакета

1. Использовать завершённый защищённый production-билд владельца. Проверить фактическую версию EXE, состав и подтверждение сборки.
2. Подготовить отдельный публичный пакет с теми же EXE и runtime-файлами. Не переносить PDB, исходники приложения, логи, персональные конфиги, токены, ключи и метаданные сборки.
3. Сохранить необходимые публичные компоненты среды выполнения и их лицензии. Обновить пользовательскую инструкцию; служебные и закрытые материалы исключить.
4. Сверить runtime-файлы с исходным билдом. Проверить внутренние manifests, состав вложенных архивов, контрольные суммы, отсутствие секретов и выполнить доступную антивирусную проверку.
5. Сформировать SHA-256 ZIP, внешний файл `.sha256` и внутренний `SHA256SUMS.txt`. Для v4.2.0 имя архива — `StabiLink-Desktop-v4.2.0-win-x64.zip`.

## Документация и Git

1. Согласовать README, CHANGELOG, инструкции и уведомления сторонних компонентов с фактическим пакетом. Исторические описания старых релизов сохранять как историю.
2. Проверить локальные ссылки и якоря, итоговый diff и allowlist. Запустить `.safety/verify-public-repo.ps1 -Mode Full` перед commit и push, а также проверки Staged/PrePush.
3. В Git добавить только точные разрешённые пути. ZIP и `.sha256` хранить вне checkout и загружать только во вложения Release.
4. Подготовить один Draft PR текущей ветки, выполнить проверки и ревью; после готовности перевести в Ready и объединить по правилам проекта.

## Публикация и проверка

1. Публиковать только при явном разрешении владельца на этот релиз.
2. Создать Draft Release на проверенном коммите публичной основной ветки.
3. Загрузить ZIP и `.sha256`; сверить имена, размеры и GitHub digest с локальными файлами.
4. Опубликовать Release и установить Latest для текущей стабильной версии.
5. Скачать ZIP обратно без авторизации и повторно проверить SHA-256, состав и целостность. Проверить страницу Release, README и прямые ссылки.
6. Зафиксировать результат и ограничения проверки: публикация не подтверждает игровые сессии на каждом провайдере или обновление всех установок.

Не заменяйте уже опубликованный ZIP незаметно. Для исправления используйте новую версию с новым хешем и описанием. Возврат документации выполняется отдельным revert; при критическом дефекте пакет можно снять с публикации и указать причину.
